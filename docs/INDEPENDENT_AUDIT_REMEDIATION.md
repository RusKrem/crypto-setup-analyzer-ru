## Исправленные замечания

| ID | Изменение |
|---|---|
| AUD-001 | Для кэша уровней введён предел свежести. Устаревшие уровни больше не участвуют ни в ценовых оповещениях, ни в подтверждении реакции. При истечении срока очищается незавершённое состояние подхода. |
| AUD-002 | Список контрактов использует единый helper с проверкой точных суффиксов leveraged-токенов. Маркеры внутри обычного тикера больше не исключают контракт. |
| AUD-003 | Двойной pivot одного outside-bar пропускается как неоднозначный: OHLC не содержит последовательности движения внутри свечи, поэтому нельзя честно выбрать порядок HH/LL и исполнения. |
| AUD-004 | Для Order Block определяется первая свеча инвалидирования. На графике зона завершается на этой свече и отображается приглушённой пунктирной линией с пометкой «пробит». |
| AUD-005 | SQLite-соединения в Observer-тестах закрываются явно. Для DDL-теста добавлен явный commit. Полный набор тестов включён в Windows CI. |
| AUD-P01 | Для живых данных время закрытия свечи сравнивается со временем Binance Futures. Если достоверное биржевое время недоступно, последняя свеча консервативно исключается из анализа вместо доверия локальным часам. |

## Дополнительная надёжность

- Добавлен `requirements.lock` с точными версиями разрешённых зависимостей и маркерами для различающихся версий NumPy/contourpy на Python 3.11 и 3.13.
- CI устанавливает зависимости из lock-файла и выполняет `pip-audit`.
- Windows CI теперь выполняет весь unittest suite, затем собирает Telegram Bridge и проверяет single-instance lock.
- Логирование Telegram Bridge не должно аварийно завершать обработку очереди, если консоль Windows не может вывести кириллицу: предусмотрен ASCII fallback.
