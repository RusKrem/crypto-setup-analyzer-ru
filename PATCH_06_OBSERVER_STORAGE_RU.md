# PATCH 06 — целостность архива Observer

## Область аудита

Проверены `observer/storage.py`, `observer/report.py`, тесты Observer и интеграционные тесты Telegram Bridge.

## Найденные риски и исправления

1. **Коллизии имён карточек.** Имя архивного PNG строилось после очистки queue_id от небезопасных символов. Разные идентификаторы могли получить одинаковую строку. Теперь имя содержит SHA-256 queue_id, поэтому такая коллизия практически исключена.
2. **Частично скопированный файл.** Карточка копировалась напрямую в конечный путь. Теперь она сначала копируется во временный файл в папке архива, а затем атомарно перемещается в конечное имя.
3. **Сиротская карточка при ошибке SQLite.** Файловая копия могла остаться, если вставка события или commit завершались ошибкой. Теперь при ошибке записи созданная копия удаляется, а исключение передаётся Bridge для повторной попытки архивирования.
4. **Миграция старой базы.** Добавлен регрессионный тест для базы, в которой отсутствует `metadata_json`; архивирование должно добавить столбец и сохранить событие.

## Изменённые файлы

- `tests/test_observer.py`

## Проверка

В GitHub Actions проверяются компиляция и полный набор unittest на Python 3.11 и 3.13. Итоговый результат последнего запуска следует смотреть в Actions для коммита, содержащего этот документ.

## Что не менялось

Формат событий, правила сигналов, критерии подтверждения реакции, торговые уровни и логика сканера не изменялись. Консольный отчёт `observer/report.py` в этом патче не менялся.
