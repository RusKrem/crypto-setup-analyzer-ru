# PATCH 05 — надёжное архивирование Telegram-доставки

## Найденный дефект

Telegram Bridge удалял файл очереди сразу после успешного ответа Telegram Bot API, даже если Observer не смог записать событие в SQLite. При временной ошибке диска, блокировке базы или отсутствии модуля Observer уведомление уже находилось в Telegram, но его локальная история терялась.

Дополнительно проверка фото через строковый `startswith` не защищала от символической ссылки внутри `telegram_queue`, ведущей за пределы этой папки.

## Что изменено

- После подтверждённой отправки Bridge сохраняет в JSON очереди флаг `telegram_sent`, ответ Telegram и время доставки.
- Если архивирование не удалось, запись остаётся в очереди. Следующие проходы повторяют только вызов Observer, не повторяя отправку в Telegram.
- Для повторов архивирования добавлен отдельный экспоненциальный backoff до 300 секунд.
- Очередь и изображение удаляются только после успешного архивирования или обнаружения уже существующей записи с тем же `queue_id`.
- Если модуль Observer не загружен, подтверждённая Telegram-доставка остаётся в очереди до восстановления Observer.
- Проверка изображения использует разрешённые реальные пути и отклоняет символические ссылки, выходящие за пределы `telegram_queue`.

## Изменённые файлы

- `telegram_bridge/bridge.py`
- `tests/test_bridge_observer.py`
- `TELEGRAM_BRIDGE_SETUP_RU.md`

## Проверка

GitHub Actions: полный набор из **53 тестов** прошёл на Python 3.11 и Python 3.13. Компиляция Python-исходников также прошла на обеих версиях.

Регрессионные проверки подтверждают:
- успешная отправка архивируется и очищает очередь/исходное изображение;
- при сбое Observer очередь сохраняется с подтверждением Telegram;
- повторный проход восстанавливает архив, не выполняя второй сетевой вызов Telegram;
- символическая ссылка на изображение за пределами очереди отклоняется.

## Ограничение

Как и в любой интеграции с внешним API, невозможно обеспечить абсолютную гарантию exactly-once, если процесс аварийно завершится в узком промежутке между получением успешного ответа Telegram и сохранением маркера `telegram_sent` на диск. В штатном сценарии временного отказа SQLite или Observer доставка не дублируется, а локальное архивирование повторяется отдельно.
