# PATCH 07 — целостность рыночных данных

## Найденные риски

1. Уровни предыдущего дня вычислялись через предположение, что предпоследняя строка Binance Klines всегда является вчерашней свечой, а последняя — сегодняшней. При пропущенной/задержавшейся дневной свече это могло назначить неверный период уровню.
2. Недельные экстремумы рассчитывались по тем дневным свечам предыдущей недели, которые присутствовали в ответе. Неполная неделя могла ошибочно выглядеть как полный недельный диапазон.
3. Ответ Klines использовался без централизованной проверки порядка, числовых значений и согласованности OHLC.
4. Резервный REST-снимок цены мог обработаться после более свежего WebSocket-обновления.
5. WebSocket-события не проверялись на порядок event time, а нечисловые/бесконечные цены не отбрасывались единым входным контролем.

## Что исправлено

- Добавлена валидация Klines: структура строки, числовые и конечные значения, положительные цены, неотрицательный объём, согласованность OHLC и строго возрастающее время открытия свечей.
- Дневные уровни выбираются по фактической UTC-дате открытия свечи, а не по позиции строки в массиве.
- PDH/PDL формируются только при наличии конкретной свечи предыдущего UTC-дня.
- PWH/PWL формируются только при наличии всех семи дневных свечей предыдущей календарной недели.
- Today High/Low используют только свечу, открывшуюся в текущую UTC-дату.
- REST fallback не перезаписывает цену, если по этой монете WebSocket поступал в последние 15 секунд.
- WebSocket-события с более старым event time игнорируются.
- Некорректные, бесконечные и нечисловые цены отбрасываются до обработки.
- Состояние последнего подтверждённого времени свечи теперь проверяется и обновляется под общим lock.
