# PATCH 11 — защита очереди и полный цикл доставки

## Аудит пути события

Проверен маршрут:
1. Сканер формирует предупреждение или подтверждённую реакцию.
2. UI независимо записывает событие в локальную SQLite-базу приложения.
3. TelegramNotifier формирует карточку по закрытым свечам и атомарно ставит JSON/PNG в файловую очередь.
4. Telegram Bridge отправляет сообщение.
5. После успешного ответа Telegram Bridge сохраняет подтверждение доставки в JSON очереди.
6. Observer архивирует текст, метаданные Telegram и копию изображения в собственную SQLite-базу.
7. Только после успешной архивации удаляются исходные JSON и PNG из очереди.

## Результаты аудита

- Ошибка записи локального журнала приложения не прерывает последующую попытку постановки уведомления в Telegram: обработчики UI перехватывают исключение журнала отдельно.
- Ошибка архивации Observer не приводит к повторной отправке уже принятого Telegram сообщения. Для Observer используется отдельный backoff.
- `queue_id` уникален в Observer, повторная архивация не создаёт вторую запись.
- Медиа сначала атомарно копируется в архив, затем фиксируется строка SQLite; при ошибке вставки копия удаляется.
- Исходный PNG удаляется только после успешного завершения архивации.

## Изменения PATCH 11

### Просроченные карточки
Если TTL карточки истёк до отправки, Bridge теперь удаляет и JSON, и связанный PNG (только если изображение находится внутри каталога очереди). Ранее PNG мог оставаться сиротой.

### Повреждённые JSON
Нечитаемый JSON больше не остаётся в активной очереди и не перечитывается каждую секунду. Он переносится в `telegram_queue/failed/` с исходным содержимым для ручного разбора. Автоматическая отправка таких элементов не выполняется.

### Регрессионные тесты
Добавлены проверки удаления PNG у просроченного события и карантина повреждённого JSON без обращения к Telegram API.

## Ограничения

- Telegram Bot API не предоставляет idempotency key для sendMessage/sendPhoto. Если Telegram принял сообщение, но процесс аварийно завершился до фиксации `telegram_sent` на диске, при следующем запуске возможна повторная отправка. Это окно неопределённости невозможно полностью закрыть только локальным JSON-файлом.
- Карантин сохраняет повреждённый JSON, но не может восстановить неизвестные поля и связанные пути к медиа.
- Telegram Bridge должен работать из той же корневой папки приложения, где находятся `telegram_queue`, `.env` и `observer_data`.

Торговые параметры, уровни, направления и критерии подтверждения не менялись.
