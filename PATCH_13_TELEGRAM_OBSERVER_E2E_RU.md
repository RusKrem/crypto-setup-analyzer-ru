# PATCH 13 — Сквозная доставка Telegram → Observer

## Цель

Укрепить локальный конвейер доставки событий: очередь приложения → Telegram Bridge → Telegram Bot API → Observer SQLite и архив медиа. Торговые условия, уровни, пороги и правила подтверждения не менялись.

## Изменения

### Telegram Bridge

- Добавлена проверка структуры JSON очереди до чтения полей. Некорректный корень, идентификатор, числовые поля и противоречивое состояние уже отправленного события отправляются в `telegram_queue/failed/` для ручного разбора, а не останавливают основной цикл Bridge.
- Запись состояния очереди остаётся атомарной; перед заменой JSON файл сбрасывается через `flush()` и `os.fsync()`.
- Временный файл `.tmp` очищается при успешной замене и при ошибке.
- Ошибка удаления JSON после успешной архивации Observer не останавливает Bridge. Файл остаётся в очереди с `telegram_sent=true`; следующий проход повторяет только безопасную архивацию/очистку, не отправку Telegram.
- Отдельный backoff архивации Observer сохраняется независимо от сетевых попыток Telegram.

### Проверки

Добавлены интеграционные тесты:

- успешная отправка, запись события и копирование PNG в Observer до удаления исходников;
- сбой Observer после успешной отправки Telegram и повтор архивации без повторной отправки;
- повтор архивации с реальным SQLite Observer и PNG: исходная карточка сохраняется до успешной архивации, затем удаляется;
- повреждённые и структурно некорректные JSON-файлы уходят в карантин без вызова Telegram;
- сбой атомарной записи очищает временный файл;
- временная ошибка удаления JSON не останавливает Bridge и не вызывает повторную отправку Telegram.

## Границы гарантий

Telegram Bot API не предоставляет idempotency key для `sendMessage` / `sendPhoto`. Если Telegram принял сообщение, но процесс аварийно завершился до записи `telegram_sent=true` в локальный JSON, после перезапуска остаётся окно возможной повторной отправки. Это ограничение протокола и локальной очереди. После успешной фиксации `telegram_sent=true` повторный проход не отправляет сообщение заново.

Тесты используют подменённый HTTP-ответ Telegram, но выполняют настоящую архивацию в SQLite и файловую работу Observer. Реальная доставка в Telegram проверяется только в настроенной среде пользователя.
