# Reversal Lab Observer

Локальный архив успешно отправленных уведомлений Reversal Lab. Observer не подключается к Telegram самостоятельно, не читает чужие сообщения и не меняет торговые сигналы. Он получает копию события внутри Telegram Bridge после подтверждения успешной отправки Telegram Bot API.

## Что сохраняется

- исходный текст уведомления;
- тип события (`LEVEL_APPROACH`, `REACTION_CONFIRMED` и другие);
- монета, направление, название и цена уровня;
- цена и расстояние до уровня (если присутствуют в тексте);
- тень/тело и позиция закрытия (для подтверждений);
- локальная копия PNG-карточки;
- время постановки в очередь, отправки и Telegram message ID.

## Где лежат данные

После первой успешной отправки создаётся `observer_data/` в корне проекта:

- `observer_events.sqlite3` — база событий;
- `media/` — копии PNG-карточек.

Эта папка не должна попадать в публичный GitHub-репозиторий. Не отправляйте базу и карточки публично, если в них есть приватная информация.

## Просмотр отчёта

Запустите `START_OBSERVER_REPORT.bat` или выполните из корня проекта:

```bat
py -3 observer\report.py --hours 24
```

Например, отчёт за 7 дней и экспорт CSV:

```bat
py -3 observer\report.py --hours 168 --csv observer_last_week.csv
```

Повторяющиеся сочетания типа события + монеты + направления + уровня отмечаются для ручной проверки. Это не автоматический вердикт о дубликате: повторное срабатывание после выхода из зоны и повторного входа может быть допустимым.

## Важное поведение

- Архивирование выполняется только после ответа Telegram `ok=true`.
- Ошибка Observer записывается в `telegram_bridge_log.txt`, но не вызывает повторную отправку уже доставленного сообщения.
- Повторная обработка одного queue ID не создаёт вторую запись.
- Если PNG не найден или не входит в `telegram_queue`, сохраняется текст события без файла.
- Observer архивирует именно сообщения, отправленные этим приложением через Bridge. Сообщения, вручную опубликованные другими участниками канала, сюда не попадают.
