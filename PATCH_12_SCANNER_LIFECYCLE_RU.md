# PATCH 12 — жизненный цикл сканера и восстановление состояния

## Что проверено и изменено

### 1. Остановка и повторный запуск

- Свойство `running` теперь учитывает все три фоновых потока: основной REST-цикл, WebSocket и проверку подтверждений.
- Повторный `start()` не создаёт второй комплект потоков, пока любой поток предыдущего запуска ещё работает.
- При остановке сканер фиксирует состояние активных подходов на диск, даже если перед остановкой не было нового ценового события.
- После полного завершения старых потоков тот же экземпляр сканера может быть запущен повторно.

### 2. Восстановление JSON-состояния

- Проверяется, что корень JSON является объектом, а список активных записей имеет ожидаемый тип.
- Некорректные отдельные записи пропускаются.
- Нечисловые и бесконечные значения времени начала не восстанавливаются.
- Срок восстановления активного подхода по-прежнему ограничен пятью минутами.
- Уже подтверждённый подход и время последней подтверждённой свечи восстанавливаются, чтобы не отправлять повторное подтверждение после перезапуска.

### 3. Регрессионные тесты

Добавлены проверки:
- сохранения активного подхода при вызове `stop()`;
- восстановления состояния подтверждённой реакции;
- безопасной обработки JSON с неверным корневым типом.

## Границы изменений

Торговая логика не менялась:
- порог приближения — 0,5%;
- гистерезис — 0,7%;
- направления LONG/SHORT;
- условия оценки rejection;
- временное окно подтверждения — пять минут.

Проверки unit-тестов выполняются в CI на Python 3.11 и 3.13. Этот патч не заменяет ручной GUI-тест на Windows и проверку сетевого завершения реальных REST/WebSocket-запросов.
