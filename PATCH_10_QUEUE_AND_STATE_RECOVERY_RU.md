# PATCH 10 — надёжность очереди и восстановление подходов

## Что изменено

### 1. Очередь Telegram

В `TelegramNotifier` добавлена единая функция атомарной записи JSON:

- создаёт каталог очереди внутри защищённого блока обработки ошибок;
- сериализует данные до записи;
- записывает временный файл и затем атомарно переименовывает его;
- удаляет временный файл при ошибке;
- для карточек удаляет PNG, если постановка в очередь не удалась;
- запрещает передавать в очередь изображения, расположенные вне `telegram_queue`;
- проверяет, что файл карточки существует.

Ошибки записи возвращаются вызывающему коду как неуспешный результат, а не маскируются успешной постановкой.

### 2. Состояние активных подходов

Сканер получил необязательный параметр `state_path`. В основном окне он указывает на:

`data/rebound_scanner_state.json`

Сохраняются:
- ключ активного уровня и календарного периода;
- время начала подхода;
- последняя проверенная свеча;
- признак уже подтверждённой реакции.

Запись состояния атомарная: временный JSON заменяет основной файл только после полной записи.

При запуске восстанавливаются только активные подходы, начавшиеся не более пяти минут назад. Просроченные записи игнорируются. Повреждённый файл состояния не блокирует запуск сканера.

Состояние обновляется при изменении жизненного цикла подхода и при захвате/освобождении подтверждения.

### 3. Регрессионные тесты

Добавлены проверки:
- очистки временного файла при ошибке записи очереди;
- запрета фото вне каталога очереди;
- удаления PNG при ошибке сериализации;
- восстановления активного подхода после перезапуска;
- отказа от восстановления просроченного подхода.

## Ограничения и гарантии

- Если диск недоступен или заполнен, приложение не может гарантировать физическую запись нового события. Ошибка теперь явно возвращается вызывающему коду; временные артефакты очищаются.
- Восстановление состояния ограничено пятью минутами, чтобы не оживлять устаревшие подходы.
- Состояние сканера локальное для одного экземпляра приложения. Оно не является распределённой блокировкой для нескольких одновременно запущенных копий.
- Идемпотентность отправки в Telegram по-прежнему ограничена возможностями Bot API.

Торговые условия не менялись: порог приближения 0,5%, гистерезис 0,7%, направления LONG/SHORT и критерии rejection сохранены.
